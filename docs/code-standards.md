# 代码与验收规范

由 2026-10-14 的“提交推送，然后实施 qi-agent 实施方案”任务采用。后续规则变化单独审查。

1. 行为修复提供旧实现上的目标断言失败和新实现上的通过；语法错误、零测试和 skip 不是有效 red。纯文案在任务开始前说明豁免。
2. 固定 base / candidate SHA、profile、控制器、验收器和环境。脏工作区不能借用 HEAD 的 CI 绿灯。
3. 验收器在候选写权限之外；必需项不能在实现后改成可选。未知结果写 UNKNOWN，未运行写 NOT_RUN。
4. 检查保存命令、平台或镜像、起止时间、退出码、可取得的测试数及原始输出。原始输出保留在私有状态目录。
5. 按影响范围运行完整测试、生产构建及端到端检查；mock 证据不外推为真实 provider、桌面或模型能力。
6. 基线失败先阻断并定位；候选文件范围、审查 head、集成 base 任一变化都使旧证据失效。
7. 中断、超时、写入失败和响应丢失必须有恢复路径；未知副作用不自动重放。
8. 费用包括失败、重试、子任务与压缩。已知小计和完整总额分开；缺失总额保持 null。
9. 模型结果完成、候选验收、人工接受、合入和发布是不同事件。发布必须绑定精确已验证 SHA、完整资产和校验和。
10. LESSONS 只归纳实际事故；同一事故的反复检查不增加 Seen，不自动升级项目规则。
